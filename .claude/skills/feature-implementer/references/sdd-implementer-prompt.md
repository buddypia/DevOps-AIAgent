# Implementer Subagent Prompt Template

feature-implementerのSDDモードでタスクごとの実装サブエージェントをディスパッチする際に使用するテンプレート。

```
Agent tool (general-purpose):
  description: "Implement Task N: [task name]"
  prompt: |
    Task N: [task name]を実装します。

    ## タスク説明

    [PLAN.mdからタスク全文を貼り付け — サブエージェントにファイルを読ませない]

    ## コンテキスト

    [このタスクが全体のどこに位置するか、依存関係、アーキテクチャコンテキスト]

    ## 開始前に

    以下について質問があれば**今すぐ聞いてください:**
    - 要求事項や受け入れ基準
    - アプローチや実装戦略
    - 依存関係や前提
    - 不明な部分

    **作業中にも**予期しないことや不明なことがあれば質問してください。
    推測したり仮定したりしないでください。

    ## 作業内容

    1. タスクに明記された内容を正確に実装
    2. テストを作成（タスクがTDDを要求する場合はTDDに従う）
    3. 実装が動作するか検証
    4. 作業をコミット
    5. セルフレビュー（下記参照）
    6. 報告

    作業ディレクトリ: [directory]

    ## 限界を超えたとき

    止まって「これは自分には難しすぎる」と言うことは常にOKです。
    悪い作業は作業なしより悪いです。

    **止まってエスカレーション:**
    - 複数の有効なアプローチがあるアーキテクチャ決定が必要なとき
    - 提供された範囲を超えてコードを理解する必要があるとき
    - アプローチが正しいか不確実なとき
    - 計画が予期しない形で既存コードを再構成する必要があるとき

    **エスカレーション方法:** BLOCKEDまたはNEEDS_CONTEXTステータスで報告。

    ## 報告前: セルフレビュー

    **完成度:** スペックのすべてを実装したか? 見逃した要求事項は? 処理していないエッジケースは?
    **品質:** 名前は明確で正確か? コードはクリーンで保守可能か?
    **規律:** YAGNIに違反していないか? 要求されたものだけを作ったか? コードベースの既存パターンに従ったか?
    **テスト:** テストは実際の動作を検証しているか（モックの動作ではなく）? TDDに従ったか?

    セルフレビューで問題を発見したら、報告前に今すぐ修正してください。

    ## 報告フォーマット

    - **Status:** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
    - 実装した内容（または試みた内容）
    - テストした内容とテスト結果
    - 変更されたファイル
    - セルフレビューの発見事項
    - 問題や懸念事項

    DONE_WITH_CONCERNS: 作業を完了したが正確性に疑問があるとき。
    BLOCKED: タスクを完了できないとき。
    NEEDS_CONTEXT: 提供されていない情報が必要なとき。
    確信のない作業を黙って提出しないでください。
```
